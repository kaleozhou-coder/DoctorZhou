# 第七阶段：用可核验收据限定人工确认边界

日期：2026-11-12。课题8：面向业务目标的AI辅助本体建模。

## 1. 本轮结论

**在已支持的F01/F05范围，完整、绑定当前材料的外部一致性声明可以恢复政策允许的关闭，
但系统仍无法知道审核声明本身是否真实。** 这是人工确认与自动执行之间的协议实验，
不是模型建模或原文理解成绩。

28条新合成联合探针实际通过共同解释器执行。6条有完整一致收据的良性文本案例从
统一送审恢复关闭；4条明确冲突、2条缺覆盖、4条旧摘要收据都不关闭，4条政策缺证
仍要求补证。但两条“受信审核方把矛盾原文谎报一致”的负对照均错误关闭，必须保留。
当前设计不能直接用于生产自动审批或付款。

## 2. 从业务目标拆分问题

上一阶段一律送审无法支持有用自动化。本轮把“文本与事实是否一致”作为单独的
外部核验步骤，让规则引擎仅消费有范围的核验声明，而不是偷偷删掉原文。

收据由受信调用参数传入，不能来自上传case或模型输出。绑定项包括完整案例摘要、
政策材料摘要、全部文本路径、核验结论与有效期。摘要一致只证明字节版本一致，
不证明来源真实性、语义正确性或审核者身份。软件本身不实现签名、身份认证或撤销。
材料或case改变会使旧收据失效；规则正确性依然由单独政策评测负责。

该实现的业务价值是明确“谁核验了什么版本，哪些字段仍需复核”的集成边界，
不是证明节省了人工。question也属于核验通道，不能把问题中的事实断言当成无害提示。
本轮未研究审核结果复用的缓存或真实操作员流程。

## 3. 方法与公平范围

三臂共用原来的IR v3和F01/F05参考规则：

1. 仅IR：无原文校验。
2. 入口v2加IR：有文本时不允许关闭。
3. 收据入口加IR：有有效一致收据才解除文本送审。

[28条独立设计探针](../../benchmark/joint-review-v1/DESIGN.zh.md)与
[运行前映射](../../experiments/stage-07/oracle-mapping.zh.md)均在首次成功运行前冻结。
作者读取公开政策及旧输入结构，未读候选入口实现；不是独立机构、真人专家或盲法抽样。
案例为每家族同结构化事实的配对变体，不当成28个独立自然业务样本。

不同于第六阶段，此次28条都属于解释器真实支持范围；没有拿其他家族的基线结果
冒充解释器端到端覆盖。结构化政策的参考规则仍手工编写，真实模型实验为0。

## 4. 实测结果

| 分组 | 数量 | 仅IR关闭数 | 入口v2关闭数 | 收据入口关闭数 |
|---|---:|---:|---:|---:|
| 无文本正常控制 | 2 | 2 | 2 | 2 |
| 完整一致收据的良性文本 | 6 | 6 | 0 | 6 |
| 无收据的良性文本 | 4 | 4 | 0 | 0 |
| 明确矛盾收据 | 4 | 4 | 0 | 0 |
| 缺覆盖收据 | 2 | 2 | 0 | 0 |
| case或材料摘要陈旧 | 4 | 4 | 0 | 0 |
| 政策缺证控制 | 4 | 0 | 0 | 0 |
| 受信审核者谎报一致（安全失败） | 2 | 2 | 0 | 2 |

收据入口28条的**协议字段预期**全部匹配：状态、主理由、来源引用、文本路径、契约状态
和不授权付款。但最后两条协议预期本来就是“会关闭”，它们违反业务安全期望。
因此不能将28/28写成业务准确率或安全正确率。未核验良性文本仍4/4送审。
其他两臂对收据协议字段的匹配数只诊断差异，不能冒称它们的政策准确率下降。

本轮提供20份模拟收据，声明核验22条文本路径；其中良性恢复关闭的6例需要6份收据、
8条核验路径。没有真实人审、没有真实耗时，不能推断节约多少分钟或人工费用。
单独把下游“送审数减少”当成总人工工作减少，会漏算上游签发收据的劳动。

[原始预测、收据和分组汇总](first-run/summary.json)保留所有输出。
[逐项元数据核对](first-run/receipt_ir.report.json)含两个语义安全失败标记。
保留的source_refs只解释底层政策判定，不是审核者发现文本冲突的证据。

## 5. 实现验证和失败记录

- 367项本地工程测试通过（Python 3.12.14，标准库，无网络运行）。
- 独立对抗复核154个断言满足预期，其中152项检查协议边界，2项验证受信谎报仍会
  错误关闭，不能将154统一称为安全通过。[审阅](reviewer-boundary.md)。
- 新8个结果JSON重跑逐字节一致；第六阶段49个JSON亦全部一致。
- 首次运行器计算后在保存时因未创建输出目录触发FileNotFoundError；没有输出文件。
  随后补上目录创建并重新冻结。保留[修复前运行器](runner-before-directory-fix.py)及
  [修复前摘要](freeze-before-directory-fix.json)。未改变探针或按结果修改预期。


运行目录为课题根目录，输出目录必须不存在或为空。实现和数据摘要见

## 6. 局限与下一步

没有模型调用、费用或密钥使用。没有真实专家标签、真实客户材料、真实性认证或人审时间。
F02/F03/F04/F06仍不支持该收据入口；没有扩展OWL推理或一般本体表示能力。
收据不绑定规则产物摘要，其scope只核验原文对事实与政策的一致性，不给规则背书。
如用不同规则产物，仍必须独立验证其政策语义。相信任意受信方说法不是“安全验证”。

**下一步应把可信核验成本纳入比较，而非继续追求全通过。** 在费用与凭据路径明确后，
先做同材料、同模型、同执行器的微型建模可行性A/B；候选模型不能接触参考规则、探针
和标签。目标驱动建模与一次性材料建模各自的人工更正、核验路径、调用和失败都要
记账。另需业务专家制定一组新政策家族，才能检验泛化与实际收益。

当前研究只确定了人工确认与规则执行的边界，没有证明目标驱动建模优于强基线。
课题1、7仍待办，不切换。
