# 第18阶段设计回写

这份回写是阶段设计的一部分。先保留冻结的 [理论](design/01-theory.zh.md)、[概要](design/02-overview.zh.md)、[详细设计](design/03-detail.zh.md)、[错误码](design/04-reason-contract.zh.md) 及摘要，然后再读取运行结果。独立夹具和标签的版本亦保留；不按首跑结果改金标。

| 追踪项 | 第17阶段已有能力 | 第18阶段落实边界 |
|---|---|---|
| E18-01 原文与版本 | 裸引文唯一可定位并回显摘要 | 候选引用须绑定精确文档/版本/文本层、原始/规范化摘要、位置及登记条款，同时保持 Unicode 坐标口径。定位不决定业务适用性。 |
| E18-02 权威范围和角色 | 定位与严格金标评分分开 | 逐项校验同项目、同字段及标段，独立登记 DIRECT、CONTEXT、CONFLICT。已知结论需完整直接集，且不能靠背景、草稿或跨标段同值来放行。 |
| E18-03 缺件闭环 | 答案可表达 UNKNOWN | 有唯一精确补件定义且有授权 CONTEXT 定位才是正确待核；永远不能执行。旧 UNKNOWN 是否更易恢复，尚无 A/B 结果。 |
| E18-04 发布边界 | 原型没有真实审批接入 | ELIGIBLE 仅表示可入人工复核，不签发，不产生当前生产执行授权。不可见冲突不等于不存在；生产须单独验证权威范围覆盖和权限，不向用户泄漏隐藏资料。 |
| E18-05 验收数据 | 人工编写合成原文和锚点控制 | 6 组带变化对照的夹具，外部 expected 只进计分。可信登记和 expected 同领域人工构造，不是异源真实金标；不将单元断言数作独立业务样本。 |

本阶段暂不引入 LightRAG、真实 PDF/OCR、对象映射、SPARQL/OWL/SHACL、浏览器工作台或真实 Runtime。研究扩展应先冻结配对设计、旧 UNKNOWN 的合格分母、相同复核预算，再测「全量候选自由复核」与「预留旧未知复核」的收益与退化，保持共同门禁。

### E18-06 首次运行发现：直接共证据不一定载值

冻结夹具 SP-71 把签发页和载值附件都列为必需直接证据。旧实现误要求每段都给值，首跑异常退出且没有结果 JSON。保留[首跑记录](results/first-attempt/outcome.zh.md)、旧源码和摘要。修订后依旧要求完整的直接证据集合，但允许必要的签发页不载值，至少有一个必需条款给值、所有载值条款均一致。详见[修订约定](design/05-direct-complement-fix.zh.md)。不改变夹具标签。

`UNCLASSIFIED`（第17阶段回写的界面候选状态）未纳入此门禁数据模型，未知角色作为结构错误拒收；真正工作台仍应显示可补证的未分类草稿，而不能暗中归到 DIRECT。本接口输入不带业务有效日期引擎；注册表已预置当前范围与证据，未验证动态生效与替代链求值。登记人错误或遗漏仍可使结果错误。
