# 第 18 阶段：把“能找到原文”变成可检查的证据门禁

**结论：按人工登记的适用范围、来源角色和版本，确定性门禁在六组虚构材料的 21 个候选上复现了预设结果。** 4/4 合格候选可进入人工复核，2/2 证据确有缺件的候选正确待核，15/15 负例被拦。17 个不应具资格的候选中没有误进人工复核。可进入复核不是审批通过、已发布或准允执行。六组是不同材料设计；21 个候选包含同组变体，不能当作独立自然样本，更不是生产正确率。

## 要解决的实际问题

第 17 阶段两次模型运行各答对 9/9，但严格证据分别为 7/9 与 9/9。真实引文可能来自草稿、背景或错标段。第 18 阶段不调用 LLM；冻结候选和人工证据登记，通过同一原型检验能否区分结论可用、仍需补证和不合格。候选本身不能给材料授予权威；原型也不从自然语言自行推断权威、时点、业务适用性或登记完整性。

| 合成材料家族 | 实做判定 |
|---|---|
| 角色语境 | 直接制度 + 背景允许；只给背景、把背景升为直接证据拦截 |
| 同版错标段 | B/C 同为 6 日；另一标段即使同数字且能定位也不适用 |
| 同文无签署 | 可追溯正式版本才可支持；内容相同的草稿或不可见提取版被拦 |
| 撤回且替代正文缺件 | 明确补哪份、哪条与对应原文定位则待核；猜值或补错不能通过 |
| 完整补件两段联合 | 签发页 + 载值条款一起才能支持；删签发页、改值、改摘要均拦 |
| 到件仅封面仍缺正文 | 封面能指出所缺正文，不证明值；错误定位和角色不接受 |

12 个不应具资格的候选给出了 KNOWN；“只要说自己已知就当可复核”的假设会吞下这些错误。这只是结构反例计数，非 AI 策略基线或准确率实验。其他 3 个负例也是错误候选，但其自身状态是 UNKNOWN，分别评分仍有必要。

## 首跑失败、处理与复现

按理论→概要→详细设计→冻结夹具→运行→回写。首次程序在 SP-71 的签发页（不直接载值）抛错，没有结果 JSON；保留[首次失败记录](results/first-attempt/outcome.zh.md)和源文件。问题是实现错误地要求每个 DIRECT 都载值，而冻结详细设计明确 value 可选。修订为：所有必需依据都必须到位；至少一个必需条款给出值，所有载值条款一致。夹具和金标未改。第二次 Python 3.12.14 与 3.13.5 的 [21 项逐例验收](results/acceptance.json) 结果逐字节相同；另在每个版本运行 [21 项工程测试](tests/test_gate.py)，均通过。不能将两次同样本加总当成 42 个案例。

## 边界与下一步

当前监管信息靠人造的受信登记，测试夹具作者未依赖门禁实现来生成运行标签；同一合成语境并非真实审计专家标注。模拟 ACL 只测试输入可见性，不能证明在真实授权边界不泄漏，也不证明隐藏冲突不存在。无真实客户文档、模型对照、OCR、OWL/SHACL、前端或 Runtime。无第三方模型费用。

下一步保持这一门禁和人工标注不随比较臂变化，冻结至少六组不同家族、相同首轮结果/材料/复核预算，对比自由复核与预留旧 UNKNOWN 的复核策略。分别报告值、直接证据、补件、错误可复核、稳定字段退化。当前不能断言渐进式建模已经优于一次性方案。
