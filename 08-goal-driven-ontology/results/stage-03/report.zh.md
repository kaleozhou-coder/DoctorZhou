# 课题 8 第三阶段：从政策文本到可执行规则基线

日期：2026-11-08。

## 摘要

本阶段把六份既有合成政策独立实现为确定性 Python 规则程序，在程序和运行器冻结后执行此前保留的 60 条结构化交易案例。首次运行的三态判断与主理由均与标签一致：开发集 20/20、验证集 10/10、测试集 30/30；全部 40 条负例没有被错误建议关闭，20 条可关闭案例全部识别。三个 split 的预测和报告加汇总共 7 个 JSON 文件，在独立重跑后逐字节相同。

**这是实际执行的规则基线，不是答案回放，也不是大模型建模对照。** 它没有从自然语言自动学习规则。实现由 AI 辅助编写，使用材料中已结构化的事实；没有真人标注或审阅耗时、没有真实业务凭证、没有模型 API 调用。

## 1. 研究问题与判断

上一阶段已有防漏答评分器和 60 条新合成案例，但执行结果仍主要是评分器探针，缺少一个按政策真正计算判断的程序。本阶段的问题是：只让实现者阅读政策和接口，能否独立写出与六类标签一致的可执行规则？

本次结果支持一个有限判断：**这组显式政策和结构化事实可以被确定性规则完整覆盖。** 因而未来即使 AI 在同一套题上得到满分，也不能据此证明“目标驱动分批建模”有优势。需要比较建模过程的成本、概念/规则质量及变更后的维护效果，并使用同模型、同资料、同预算的强全量方案。当前不作创新性、真实业务准确率或节省人工的结论。

## 2. 方法与信息边界

- 输入沿用第二阶段冻结包，19 个文件的 SHA256 清单不变。六家族分别覆盖序列号重叠、分订单行授权、冲突终验、撤销替代、政策过渡、引用存在但不支持结论。
- 实现者只使用六份政策、通用案例信封及输出契约，自行编写测试，没有读取评价交易、标签、生成脚本、来源登记表或旧解释器。读取清单见 [implementation-read-manifest.json](implementation-read-manifest.json)。
- 这是任务约束下的输入隔离，不是操作系统强制隔离。协调者在准备阶段看过部分 F01 开发交易及标签字段名/类型，且整个基准早已公开，不能称全盲、外部预注册或防训练污染。
- 程序的六个家族分支是手写 Python，不是通用本体语言。它直接使用 facts，不处理 OCR、自由文本理解或文档真伪。规则意义及限制见 [manual-baseline.md](../../experiments/v1/manual-baseline.md)。
- 先完成 72 项自动测试及代码审阅，再冻结 14 个代码、测试、协议、材料和读取清单文件。随后先生成并持久化全部预测，再解析标签评分。运行前完整性检查会读取标签字节计算哈希，但不解析标签语义。
- 实现冻结摘要：`fac9ef7fd1691cc8fc5c5ceff5f8c52796c08538c7906fce348c7451da58c225`。这是本地顺序与完整性记录，不是可信外部时间戳。
- 没有根据评分结果修改代码、重写首次预测或调参。运行器拒绝覆盖非空结果目录。

## 4. 引用与审阅指标不能混淆

550 个去重后的“案例内来源＋位置”引用检查全部存在，其中测试部分 300/300。但是程序返回的是全部提供的政策和事实来源清单，包含无关材料，**不是决定性证据的最小集合，也不是语义支持正确率**。语义支持率、人工修改时间及节省时间保持空值。

标签由 AI 编写，之前的独立一致性复核和本阶段代码审阅也不是领域专家金标准。本次“主理由正确”指与既有合成标签的理由码一致，不等价于真实财务解释得到专家认可。

## 5. 完整性与复现

- 72 项自动测试通过：原有 43 项、政策基线 24 个自拟测试方法、运行器 5 项。测试方法内含若干参数化边界及变形检查，72 不是交易案例数。
- 集成前发现测试材料路径仍指向独立工作包，已在冻结前改为仓库材料路径并重新通过全部测试；不涉及评价后修正。
- 7 个基线预测/报告 JSON 在第二次运行中逐字节一致。
- 原有 15 次评分器探针重跑后，31 个 JSON 与第二阶段存档逐字节一致。
- [reproduction-check.json](reproduction-check.json) 保留文件摘要；[test-run.txt](test-run.txt) 保留完整测试输出；[implementation-freeze.json](implementation-freeze.json) 保留执行前清单。
- 实际环境为 Python 3.12.14，无额外依赖、无网络请求。代码目标为 Python 3.10+，本轮没有逐个验证其他 Python 版本。

从课题目录运行，输出必须选一个新的空目录：

```sh
python -m unittest discover -s tests -v
python src/benchmark_eval.py --benchmark benchmark/v1 --verify-only
python src/run_policy_baseline.py \
  --benchmark benchmark/v1 \
  --implementation-freeze results/stage-03/implementation-freeze.json \
  --output /tmp/ontology-policy-baseline-new-run
```

v1 评分契约只有 `engineering_probe` 和 `model_run` 两种执行标记。为不修改已冻结协议，本次沿用 `engineering_probe`，另在原始记录明确写入 `method=manual_policy_baseline` 和 `baseline_kind=deterministic_policy_program_not_label_replay`。它与第二阶段故意读取答案的回放探针不同，但都不能算 `model_run`。

## 6. 局限与下一步

1. **没有 AI A/B 结果。** 当前未确认满足固定模型身份、真实 token 计量、无新增费用要求的后端。未尝试付费调用，不把未调用描述为失败或拒绝，检查范围见 [backend-check.json](backend-check.json)。
2. **没有泛化或风险保证。** 只有六个有意构造的政策家族，家族内相关，事实已经结构化。不对 60 条样例计算伪 IID 置信区间，也不把 0/40 解读为零风险。
3. **不是通用可执行本体。** 六个专用函数是后续需要超越或匹配的规则参照。它们不能直接用作 A/B 方法独立生成本体的公共解释器。
4. **输入验证有限。** 验证按决定顺序惰性执行，并非完整外部输入验证。重复事件身份、含 `#` 的来源编码和文本/facts 冲突等限制有明确说明，不能部署到真实财务流程。
5. **下一步先补公共表示。** 定义两组模型均可生成的类型、关系、带出处的规则和执行语义，在开发材料上验证解释器，再冻结模型版本与公平资源配置。之后才做真实建模对照。
6. **更有价值的对比方向。** 在保留同一资料与权限的条件下，关注无关材料负担、冲突及晚到证据后的正确修订、建模消耗和人工改动量。新数据或新协议必须另版本，不覆盖已经公开和使用的 v1。

本阶段没有客户数据、外部收费、真实采购/付款操作或真人研究。公开同步范围仅为研究代码、合成实验记录和说明。
