# 课题 8 第五阶段：入口安全的收益、代价与残余失败

日期：2026-11-10。性质：可复现的合成工程研究，真实模型 A/B 仍未运行。

## 摘要

本阶段保留旧基线，新增显式入口契约，并把共同规则表示从仅 F05 扩到 F01、F05。结果既有修复，也有反例：

- 旧压力中的 8 条范围外输入，保守拦截由 4/8 增至 8/8；旧 22 条政策内判断及主理由全部保留。
- 新的 24 条冻结挑战中，9 条不安全输入拦住 8 条，**仍有 1 条原文拒绝、结构化字段接受的案例建议关闭**。
- 保守性有代价：新 10 条正常可关闭控制只保留 9 条；5 条良性扩展有 4 条被送审。旧 60 条的三态与理由一致数从 60 降到 57，正例关闭召回从 20/20 降到 17/20。
- 共同 IR v2 在 F01、F05 的旧 20 条案例上判断及理由 20/20，另外 40 条不支持、未执行。不能写成覆盖六家族。
- 228 项工程测试通过，25 个结果 JSON 第二次运行逐字节一致。但发布前对抗审阅另发现 IR v2 枚举校验提前返回，畸形规则可绕过默认不关闭约束；这是启动不可信模型产物执行前的阻塞项。模型建模运行数、付费调用数均为 0。

**核心结论：输入校验可以修复已知结构问题，但“保守送审”不等于理解证据；同一种矛盾换一个输入通道，仍可能漏检。** 这些结果不证明目标驱动建模优于全量建模，也不是业务准确率或实际付款风险估计。

## 1. 起点、版本与研究对象

远端起点为 `a5ed6f5cf6d413646c146ecc47ecb0b6752e4440`。隔离副本与远端 175 个文件的 Git blob SHA1 一致；原 122 项测试通过。旧代码、基准、压力包及所有历史结果保持原字节，更新仅为新增第五阶段文件和课题 README 导航，仓库根 README 不改。

本阶段没有真实交易、客户材料、付款操作或专家标注。新增案例均为明确编造的采购验收情景。规则表示参考与入口检查均是手写工程实现，不是任何模型实验臂输出。

## 2. 显式入口契约

[input_contract.py](../../src/input_contract.py) 与 [契约说明](../../protocol/input-contract-v1.md) 独立于旧基线：

- 严格 UTF-8/JSON，拒绝重复键、非有限值、浮点数及错误类型；限制字节、深度、节点及集合长度。
- 六家族的封闭对象结构，连政策本来会忽略的记录也验证；不认识的字段不会悄悄丢弃。
- 验证显式验收状态、订单行、事件 ID 冲突及已知事实合并/附件一致性。
- 统一函数 `apply_contract(case, materials, predictor)` 可以包装旧基线或共同 IR，不为不同候选系统定制规则。
- 对 `raw_text` 和 F06 段落文本采取保守处理：如果原预测会关闭但文本未经核验，改为送审。不会用关键词或自报“已验证”标志伪装语义理解。

契约仍有重要假设：F02 不提供状态时沿用正向验收前提；F05 不提供验收订单行时沿用已正确映射前提；旧 `source.text` 被当成描述性元数据而不参与关闭约束。这些兼容性选择没有验证外部来源真实性。

### 旧数据回归：修复与代价必须一起报

| 指标 | 原规则 | 原规则加入口契约 |
|---|---:|---:|
| 旧 60 条三态/主理由正确 | 60/60 | 57/60 |
| 旧负例错误关闭 | 0/40 | 0/40 |
| 旧正例关闭召回 | 20/20 | 17/20 |
| 旧压力政策内精确判断 | 22/22 | 22/22 |
| 旧压力范围外不关闭 | 4/8 | 8/8 |

旧 S25、S26、S27、S29 四个漏检均不再关闭，但旧 F06 的三个正例因携带未经核验文本而送审。这不是新的精确业务分类能力。入口实现者在冻结前已经读取旧 60 条输入和压力探针，并做过基线输出比较；因此这里只能称为回归修复，不能声称盲测提升。实现者未打开旧标签，但这一点不消除开发暴露。

## 3. 新冻结挑战：没有被“8/8 修复”遮住的失败

[entry-challenge-v1](../../benchmark/entry-challenge-v1/README.md) 在未读取新实现、单元测试和旧评价输入/标签的情况下编写，作者知道旧失败类别。24 条输入组成 12 对，有意分成三种不同评价范围；不是独立业务样本或专家金标准。

| 范围 | 原规则 | 原规则加入口契约 |
|---|---:|---:|
| 正常可关闭控制：精确判断/理由 | 10/10 | 9/10 |
| 不安全输入：不建议关闭 | 2/9 | 8/9 |
| 良性扩展：保守送审数 | 0/5 | 4/5 |

三个分母禁止合并为“准确率”。良性扩展没有精确业务标签，其送审数衡量覆盖成本；旧规则对它们全部关闭也不构成安全性优势。所有 24 条均返回结果且付款授权为 false，没有异常被当作安全拒绝。

### 残余失败 E22

F03 来源外层的 `text` 写“最终检验拒绝全部 3 EA”，`facts.inspection_register` 却为 accepted。新入口只检查外层文本的类型，将其当作描述性元数据，所以旧规则加入口仍输出 `close_eligible`。

这说明接口对文本通道的区分仍不够稳健，不能宣传为“已验证原文与字段一致”。E22 是事先定义的摄入安全边界，不是将 F03 政策事后改成一个新的精确业务理由。首次结果保持不变，未根据这条失败修改实现或标签。

### 代价 E09 及良性扩展

E09 的 F06 原文与结构化验收完全一致，也被 `contract_text_unverified` 送审。与它配对的矛盾文本 E10 同样送审：程序并未分辨二者的语义。另有四条良性扩展因附加字段或文本送审。这是可量化的保守性成本，不能藏在“零错误关闭”口号后面。

## 4. 共同可执行表示扩展

[Rule IR v2](../../protocol/rule-ir-v2.md) 在标量三值逻辑之外，加入有类型记录数组/集合、筛选、计数、交集/包含、按身份去重及冲突、集合并集和重叠检测。全部是数据式 AST，固定操作符，无任意代码执行、网络或家族专用执行分派。

参考产物仅支持 F01 的序列号覆盖及身份冲突、F05 的标量政策。F05 只变更表示版本；F01 由政策与旧代码手工编写，不是从未知材料自动归纳本体。解释器及参考产物先[冻结](../../ontology/ir-reference-v2/freeze.json)，后进行回顾性评价。

| 同一 F01/F05 范围 | IR v2 | IR v2 加同一入口契约 |
|---|---:|---:|
| 旧基准判断与主理由 | 20/20 | 20/20 |
| 旧基准正例召回 / 负例错误关闭 | 6/6；0/14 | 6/6；0/14 |
| 旧压力政策内精确判断 | 7/7 | 7/7 |
| 旧压力范围外不关闭 | 3/4 | 4/4 |
| 新挑战正常控制 | 4/4 | 4/4 |
| 新挑战不安全输入不关闭 | 1/2 | 2/2 |
| 新挑战良性扩展送审 | 0/2 | 2/2 |

完整覆盖分母：旧基准执行 20/60、未支持 40；旧压力执行 11/30、未支持 19；新挑战执行 8/24、未支持 16。不能把 IR 的小分母与旧基线全六家族分母直接比优劣。

IR 单独仍漏掉旧 S27 和新 E06 的验收订单行矛盾，统一入口负责拦截。这进一步说明表达能力与入口可信性不是同一能力。引用定位存在也不证明引用蕴含规则。

限制包括：集合上限 128、执行步数 4096；访问到的集合会积极验证，因此不相关畸形记录也可能导致保守结果；尚无授权聚合、替代关系图等能力，F02/F03/F04/F06 未支持。该解释器不是完整 OWL/SHACL 本体系统。

### 发布前发现的结构校验绕过

工程测试通过不构成安全证明。发布前审阅中，向字段枚举提供 `[null]`，会使 `_validate` 提前返回 UNKNOWN 而不是报错；`evaluate` 没有检查该返回值，继续执行。实际最小复现使用空规则列表和 `close_eligible` 默认分支，仍得到关闭建议，尽管两者都违反规范。付款授权仍为 false，但这不抵消错误关闭风险。

这一失败针对畸形规则产物，不是前面正常 F01/F05 参考产物的业务评价输入，因此没有重写旧的 20/20 或首轮结果。**当前冻结 IR v2 不能直接接收不可信模型产物，不具备真实模型 A/B 的执行准入条件。** [最小复现脚本](adversarial-artifact-probe.py)、[实际输出](adversarial-artifact.json)、精确原因及代码位置见 [审阅记录](code-review.md)。保留原实现和失败以便复现，后续修复必须另行版本化并增加负向校验测试，不覆盖本阶段首轮证据。

## 6. 实证边界与下一步

真实模型 A/B 建模运行仍为 **0**。[后端检查](backend-check.json) 只反映当前云执行环境及可用工具，没有建立固定模型快照、实际 token 计量和已确认费用边界的实验后端。没有尝试付费模型调用，不把未执行描述为服务被拒绝，也不据此断言所有模型服务不可用。

下一阶段优先级：

1. 先修复枚举提前返回，要求验证结果必须明确 valid，覆盖 null/缺失/嵌套集合枚举和非法默认分支的对抗测试；采用新版本保留本阶段失败。
2. 定义可信摄入来源与文本通道，明确何时只能送审、何时允许使用经核验结构化事实，保留 E22 作为失败证据；不能依靠字段改名或关键词补丁假装理解。
3. 用新的、未参与开发的输入组合确认这个安全/覆盖权衡；加入真实业务专家标注前仍保持合成结论。
4. 在解释器安全、后端、费用和计量条件明确后，先做缩窄范围的真实模型可行性试运行。正式优越性比较必须使用新政策家族与隔离评价，不能在已反复使用的旧 60 条上做确认性论断。

课题 1、7 保留后续待办。本阶段只能支持“工程边界被更清楚地测量，部分结构问题得到修复”，不能支持“AI 建模更好、生产可用、真实业务零风险或节省人工时间”。
