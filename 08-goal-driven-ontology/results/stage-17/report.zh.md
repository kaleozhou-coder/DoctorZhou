# 第 17 阶段（2026-11-22）：从原始条款到可定位候选
## 结论
本轮把验证起点从整理过的业务字段提前到原始中文条款：两组全虚构采购材料、8 份纯文本文档、9 个业务问题，实际交给两个不继承研究历史的内部模型上下文。两次都答对 9/9，合计 30 条引文能在指定文档快照中唯一定位；但按事先冻结的严格证据合同，联合结果分别是 **7/9、9/9**。差异不是猜错规则或引用不存在的文字，而是第一次在两个结果中额外附上了未许可的旧文件引用。复核发现它们指明附件，不提供新值也不与结论冲突，说明产品得区分「直接证明」和「解释材料来历」；简单拒绝所有背景文档会增加人工复核工作，更不能因此放宽草稿的发布权限。
    
## 步骤与理论
1. **理论**：先用业务能力问题限定要生成什么候选；[Grüninger 与 Fox](https://eil.mie.utoronto.ca/wp-content/uploads/enterprise-modelling/papers/gruninger-ijcai95.pdf) 提供按能力问题界定本体的思路。[W3C Web Annotation](https://www.w3.org/TR/annotation-model/#text-quote-selector) 启发引文与位置标记；[PROV-O](https://www.w3.org/TR/prov-o/#wasQuotedFrom) 描述引用或派生，不替我们断言材料已经签发或适用。这里借鉴思路，不声明标准一致性。
2. **方案**：原文快照 → AI 候选 JSON → 独立机械定位 → 冻结参考标签核验 → 待人工决定。设计三件套于 01:54:17 UTC 固定。题目、语料、标签、提示、评分器和工程控制于 01:57:34 UTC 固定 SHA-256 后才发起调用。
3. **实施**：Python 标准库，按 UTF-8/无 BOM、LF、NFC 建立读取表示，记录原字节和规范化表示两个 SHA-256。引文使用 Unicode code point 左闭右开坐标；只接受唯一出现，包含重叠判定。不是 byte 或 UTF-16 偏移；可见字形边界未实现，也不是对 Web Annotation 所有 selector 的实现。
4. **评价**：两次相同提示，分开上下文，不把标签、评分或另一份答案送给任一运行。只有调用封装中的一次固定提示读取，无额外材料、检索或失败重试。使用内部助手推理，确切后台模型构建、采样参数和实际 token 未暴露。输出是实际返回对象的逐条 JSON 记录；同一语料重复，不做方法优劣对照。冻结参考标签由 AI 角色预写和复核，不是独立真人专家签署真值。

## 观察到的结果
| 运行 | 业务值+状态（题） | 所有引文可定位（题） | 可唯一定位引文（条） | 严格直接证据（题） | 联合（题） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 9/9 | 9/9 | 16/16 | 7/9 | 7/9 |
| 2 | 9/9 | 9/9 | 14/14 | 9/9 | 9/9 |

- **范围和缺件**：两个运行均认定仅一标段电压改为 300，二标段 320 与 IP54 不变；只补齐附件第 3 条得到 36 个月，未擅自补出第 7 条要求的照片数量。号码待供应方交付，两次都保留未知。
- **同样的文字，不同的权威**：22:30 在未签发供应商草案和采购人签发件都出现。两个实际输出都引用签发件。故意改成引用真实供应商草案，值仍对、引文仍唯一，但预写规则证据核验不通过。引用真实性不能替代版本有效性。
- **为什么第一次只有 7/9**：Q4 的 D3 已支持保修 36 个月，D1 只是旧版指向附件第 3 条；Q8 的 D8 已支持留存 180 天，D5 只是原正文指向迁移附件。这两道题都匹配了全部必要短语，但超出该题的冻结文档白名单而失去联合分。按事后分项复核（AI 角色，不是外部人审），只将这两段明确无冲突的背景引文不作扣分，两个结果均可解释为 9/9。这个观察**不是主分**，未改冻结标签、评分脚本或实际输出，也不允许把草案改记为直接支持。
- **工程控制**：参考标签构造的阳性对照 9/9，另外六项负向探针均触发预期：同文未签草案和不全的缺件证明可以定位但不支持；重复短引、伪造引文和未知文档不能定位；只改原文换行、规范化表示不变也因 raw SHA 不同被拒。探针不是模型频次或准确率。
- **可复现**：Linux Python 3.12.14 和 3.13.5 各 16 项工程测试，通过，两个实际输出的评分 JSON 和故意坏输入控制 JSON 跨版本逐字节一致。复核从本目录运行 [README](reproduction/README.md)；不会重新调用模型。原始候选及结果见 observed。

## 详细设计回写与下一步
见 [设计回写](design-update.zh.md)。先把来源角色和补证原因设计进工作台：**可定位、能支持、允许发布分别处理**。缺正文仍保持未知，显示具体缺哪份哪条；允许背景佐证只意味着可以呈现来源关系，不改变授权、发布或业务结论。上述纯文本评分器是独立可运行模块，不是现有平台的生产代码更新，也未完成 OWL/SHACL、OCR、真实审批、部署或真实数据验证。
    
本轮只回答小样本可行性，没有证明分批优于全量、语义判断能自动替代领域专家，或两种方法等效。下一里程碑：先为证据角色和版本范围做红黄绿候选界面契约与测试，再在至少六个真正独立家族上预先冻结同材料、同轮次、同审查名额的配对实验，比较补证是否值得把固定名额留给旧 UNKNOWN；要证明业务效果需另获真实数据和领域专家评价。
