# 第十阶段：实际内部AI政策抽取配对小试

日期：2026-11-15。**这次真正让AI从业务问题与自然语言材料生成候选，不再把下游缓存、入口校验或收据逻辑当成建模收益。** 但它是内部子代理探索小试，不是受控模型API试验，不是人工批准过的本体。

## 结论

六组纯合成双文档材料、23个预写目标命题上，独立身份遮蔽AI评分给一次全材料、固定分批、强全材料两轮自审均为23/23覆盖、23/23来源完整。**本轮没有观察到分批优势。** 确定性关键词选句辅助基线17/23，不能拿这个弱语义基线代替强AI对照宣布方法优越。

| 实际运行方法 | 抽取推理轮数 | 最终候选对象 | 目标覆盖 / 23 | 严格来源完整 / 23 |
|---|---:|---:|---:|---:|
| 一次全材料AI | 1 | 24 | 23 | 23 |
| 问题引导固定分批AI | 2 | 30 | 23 | 23 |
| 强全材料AI，自审修订 | 2 | 22 | 23 | 23 |
| 确定性关键词选句 | 0 | 23 | 17 | 17 |

对象数只是JSON粒度，不是命题数、审核工作量或耗时。合并一个对象可表达多个事实；分批产物较长不能直接解读为更差。评分员未报告未支持断言或明确危险越权，但这不是安全保证。全部99个最终候选对象仍为proposed，真人批准0、人时和货币成本null。

## 输入、实际运行及证据

[材料](../../data/stage-10/materials.json)覆盖数量/签字前提、政策替换、未定义owner、同权政策冲突、服务/实物范围差异、阈值边界与未知货币范围；所有规定均为虚构，不是采购通用事实。[23条预写目标](../../data/stage-10/gold.json)在派发抽取任务前保存，作者是协调AI，无专家标注。

三个抽取子代理均不继承历史，仅获指定输入读取授权，不看金标准或其他臂。实际AI输出分别为[一次](arm_one.json)、[分批首轮](arm_batch_pass1.json)/[最终](arm_batch.json)、[强全材料首轮](arm_strong_pass1.json)/[最终](arm_strong.json)。两个两轮臂都只有一次无答案反馈修订机会；全材料强臂不会因一次输出有遗漏而失去自审机会。没有把预写答案回放称作模型抽取。

分批首轮D1，依业务问题列出缺口；第二轮统一给D2，修订候选。**第二批由协调者固定，不按模型问题自适应选取，因此只测试固定分批，不测试自主检索。** 三个AI臂都得到同样业务问题，最终看到完全相同材料。没有额外真实人审反馈。输出为来源绑定的结构化政策命题，不是OWL本体、可执行IR或完整企业模型。

[流程](../../experiments/stage-10/protocol.zh.md)、[可复用提示](../../experiments/stage-10/prompts.md)、[运行记录](run-record.json)、[输入输出哈希](review/input-sha256.json)完整保留。本地无可用Ollama服务；未安装或启动模型，无外部模型API、密钥读取或付费API调用。内部代理推理确实发生，不能称为零算力成本。

## 身份遮蔽评分与失败样例

保存输出后以固定种子匿名排列，独立无历史评分代理仅读材料、金标准、[匿名输出](review/masked.json)。完成后才由协调者[揭盲](review/reveal.json)。[逐目标92条判断](blind-grades.json)和[评分说明](blind-review.md)保留。只是遮蔽身份，输出风格仍可能暴露方法；不是完全双盲。评分员自己也是AI，独立角色不等于专家或人工评价。

确定性选句器漏掉六个目标：S02照片和承运方确认两项证据，S04数量匹配和签收两项条件，S05采购单不可替代证书，S06其他币种资格未知。原因是关键词并未覆盖needs、closes if、cannot、says nothing等表达。规则代码没有读答案，但作者先见过金标准，不能当独立盲基线。

评分中保留了判断敏感点：选句器S04含原文的“policy conflict”与无优先级，所以按显式冲突给分，不是把互相矛盾两条简单并列就当冲突识别。S03未定义owner和两角色均未指定合起来算未知。S02旧审批人只有结合明确替换语句才不算误报当前规则。未来应增加无显式“冲突”字样、长距离替换及误导证据，避免现有简单材料的天花板。

**金标准自身也有缺陷：** S04原文“closes if”表达充分条件，目标表以requires概括条件，混淆充分/必要。评分员按 intended conditions 宽松匹配，未惩罚此差别。本轮不事后改标签或重写首轮输出。这个问题限制23/23的含义，后续必须把充分/必要/仅当分开并由独立审阅者冻结标签后另开新题，不能把本次满分宣传成逻辑正确率。

## 复现与检验

课题目录内，Python 3标准库、无网络：

```sh
python -B -m unittest discover -s tests
python -B src/run_stage10_baseline.py \
  --materials data/stage-10/materials.json --output /tmp/stage10-rule-new.json
python -B src/stage10_artifacts.py --prepare /tmp/stage10-review-new \
  > /tmp/stage10-summary-new.json
cmp /tmp/stage10-summary-new.json results/stage-10/summary.json
```

输出目标须不存在或为空，避免覆盖首轮证据。全套**406项测试通过**，新增6项覆盖同材料拆分、最终候选结构/proposed、选句复现、匿名包复现与防覆盖、评分目标完整性和冻结输入哈希。匿名包、摘要和确定性基线可逐字节复现；**这些命令不会重跑AI抽取或评分**。原AI输出是冻结观察，没有可锁定的模型版本、采样种子或token账本，不承诺同输出复现。工程测试通过不等于模型正确。

## 不得推出的结论

- 无严格token/算力/延迟预算配平。全材料第二轮重复材料，分批保留历史，累计上下文不同。不能计算节省成本或单位token收益。
- 每方法只有一次小试，六案相关、作者同源；不做显著性、泛化、安全或真实业务准确率宣称。
- 当前没有真实人工审阅、专家金标准或人审时间，模型自审不能替代批准。所有候选保持待审，未知和冲突不会自动清除。
- 不能从三个满分推出等价，更不能推出目标驱动胜出。结果只表明这些简单题不足以区分流程。
- 不宣称业务问题/分批方法本身新颖。下一轮应优先改进抽取实验难度、独立标签及预算控制，而非继续增加下游机制来代替原研究问题。
